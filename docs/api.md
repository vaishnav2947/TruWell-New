# TruWell Pharmacy API Design

## Base URL
```
/api/v1
```

## API Standardisation

All REST endpoints follow a consistent pattern to ensure predictability and ease of use.

### Request Format
- **Content-Type**: `application/json`
- **Headers**: 
  - `Authorization: Bearer <access_token>`
  - `X-Request-ID: <unique_request_id>` (generated by client or server)
  - `Idempotency-Key: <unique_key>` (for POST/PUT/PATCH operations where applicable)

### Response Format

#### Success Response
```json
{
  "success": true,
  "data": { /* payload */ },
  "message": "Optional human-readable message",
  "pagination": { /* present only for paginated endpoints */ }
}
```

#### Error Response
We use a consistent error format inspired by RFC 9457 (Problem Details) but adapted for our needs:
```json
{
  "success": false,
  "error": {
    "type": "https://api.truwell.pharmacy/errors/validation-error", // URI identifying error type
    "title": "Short human-readable summary",
    "status": 400, // HTTP status code
    "detail": "Detailed human-readable message specific to this occurrence",
    "instance": "/api/v1/patients/123", // URI identifying the specific occurrence
    "violations": [ /* Array of field-specific errors for validation */ ]
      {
        "field": "email",
        "message": "Must be a valid email address"
      }
    ]
  }
}
```

### Common Query Parameters
All list endpoints support:
- `page`: Page number (default: 1)
- `limit`: Items per page (default: 20, max: 100)
- `sort`: Sort field and direction (e.g., `sort=createdAt:desc,name:asc`)
- `filter`: JSON-encoded filters (e.g., `filter={"status":"active","createdAt":{"gte":"2024-01-01"}}`)
- `search`: Full-text search term
- `include`: Comma-separated list of related entities to include (for performance)

### Rate Limiting
- Default: 100 requests per 15 minutes per IP
- Auth endpoints: 5 attempts per 15 minutes per IP
- Headers returned: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`

### Idempotency
POST, PUT, and PATCH endpoints that create or modify resources support idempotency via the `Idempotency-Key` header. Reusing the same ID will return the same response without side effect.

## Authentication
- All endpoints (except auth) require JWT in Authorization header: `Bearer <token>`
- Auth endpoints:
  - POST `/auth/register` (Super admin only)
  - POST `/auth/login`
  - POST `/auth/refresh`
  - POST `/auth/logout`
  - POST `/auth/mfa/setup`
  - POST `/auth/mfa/verify`
  - POST `/auth/forgot-password`
  - POST `/auth/reset-password`
  - GET `/auth/verify-email/:token`
  - GET `/auth/me` - Get current user
  - PATCH `/auth/me` - Update own profile

## User Management (Admin)
```
GET    /users                  - List users (paginated, filterable, sortable)
GET    /users/:id              - Get user by ID
POST   /users                  - Create user
PATCH  /users/:id              - Update user
DELETE /users/:id              - Soft delete (set inactive)
GET    /users/:id/sessions     - Get active sessions
DELETE /users/:id/sessions/:sid - Revoke session
GET    /users/:id/refresh-tokens - Get refresh tokens
DELETE /users/:id/refresh-tokens/:rtid - Revoke refresh token
```

## Prescription Management
```
GET    /prescriptions               - List prescriptions (search, paginate, filter, sort, status)
GET    /prescriptions/:id           - Get prescription by ID
POST   /prescriptions               - Create prescription (draft)
PATCH  /prescriptions/:id           - Update prescription
DELETE /prescriptions/:id           - Cancel prescription (if draft, else mark cancelled)
POST   /prescriptions/:id/submit-for-review - Submit for clinical review

POST   /prescriptions/:id/mfa-verify - Verify MFA before sending (Required for sending)
POST   /prescriptions/:id/mark-delivered - Mark as delivered (pharmacy confirmation)
POST   /prescriptions/:id/complete  - Mark as completed (patient received)
POST   /prescriptions/:id/archive   - Archive prescription
GET    /prescriptions/:id/items      - Get prescription items
POST   /prescriptions/:id/items      - Add prescription item
PATCH  /prescriptions/:id/items/:itemId - Update prescription item
DELETE /prescriptions/:id/items/:itemId - Remove prescription item
GET    /prescriptions/:id/documents  - Get prescription documents
GET    /prescriptions/:id/timeline   - Get prescription timeline
POST   /prescriptions/:id/generate-pdf - Generate PDF (async, returns job ID)
GET    /prescriptions/:id/pdf        - Get PDF URL (if generated)
GET    /prescriptions/:id/audit      - Get audit log for prescription
GET    /prescriptions/:id/workflow-history - Get workflow transition history
```

## WebSocket Events (Socket.IO)
### Namespace: `/notifications`
- `connection` - Client connects
- `disconnect` - Client disconnects
- `notification` - New notification received (payload: { notification })
- `prescription-status-update` - When prescription status changes (payload: { prescriptionId, status })
- `new-consultation` - New consultation assigned to user
- `system-alert` - System-wide announcements

### Events emitted by client:
- `subscribe-prescription` - Subscribe to prescription updates (payload: { prescriptionId })
- `unsubscribe-prescription` - Unsubscribe from prescription updates

## Reference Number Generation
Reference numbers are generated server-side and guaranteed unique. Format: 
`<PREFIX>-<YEAR>-<SEQUENCE>` 
(e.g., RX-2026-000001). Sequences reset yearly per tenant.

## Multi-Tenancy
All tenant-scoped endpoints automatically filter by `tenantId` from JWT token. Cross-tenant access is prohibited.

## Versioning
API versioned via URL: `/api/v1/...`. Deprecation policy: 6 months notice before removing v1.

## Security Headers
- Content-Security-Policy
- X-Frame-Options: DENY
- X-Content-Type-Options: nosniff
- Referrer-Policy: strict-origin-when-cross-origin
- Strict-Transport-Security (HSTS)
